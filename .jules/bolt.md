## 2024-06-22 - Deepcopy Bottleneck in Observability Snapshot
**Learning:** `copy.deepcopy()` is significantly slower than `json.loads(json.dumps())` for nested dictionaries that only contain JSON-serializable primitives. In `status_surface.observability_snapshot()`, using `deepcopy` on the large cached snapshot becomes a measurable bottleneck compared to a JSON roundtrip serialization. The memory also states "replacing it with `json.loads(json.dumps())` or `dict()` to improve performance carries significant risks... Only apply these replacements if the objects strictly require only shallow copying or are 100% JSON-compatible without semantic shifts." Since `status_surface` outputs an API response, the dictionary is strictly composed of JSON primitives (strings, ints, lists, dicts) without semantic shift risks.

**Action:** Replace `copy.deepcopy(payload)` with `json.loads(json.dumps(payload))` in the `observability_snapshot()` read path within `status_surface.py` to accelerate cache reads, as the data strictly meets JSON compatibility requirements.
