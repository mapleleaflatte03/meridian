# Meridian Message Contract

Canonical positioning definitions. All repo copy, docs, and public surfaces must align with these sentences. If a surface drifts from this contract, the contract wins.

## Core Definitions

- **Meridian** is the governed AI agent platform: runtime, governance, and trust in one installable stack.
- **Loom** is the product you install and use — a local runtime for AI agents with built-in governance, memory, channels, and verifiable proof.
- **Kernel** is the built-in governance engine that enforces authority, treasury controls, court rules, and sanctions across every agent action.
- **Intelligence** is the interface layer: dashboards, proof surfaces, workflow galleries, and operator tooling that make Loom's governance visible.

## User-Facing Sentences

- **Why install Meridian:** You get Loom — a local AI agent runtime where every action has governance, budget controls, and a verifiable receipt.
- **Why Loom is different:** Other agent runtimes give you autonomy; Loom gives you autonomy plus built-in proof that your agents followed the rules.

## Story Order (First 30 Seconds)

1. Loom is what you install and run.
2. Your agents execute locally with memory, channels, and skills.
3. Every action produces a verifiable receipt.
4. Governance (authority, treasury, court) is built in, not bolted on.
5. Meridian is the system; Loom is the product.

## Positioning Hierarchy

```
Meridian (system/brand)
├── Loom (product — the thing you install and use)
│   ├── Agent runtime, sessions, channels, memory, skills
│   └── Verifiable proof receipts (PoGE)
├── Kernel (built-in governance engine)
│   ├── Institution, Authority, Treasury, Court
│   └── 3-ledger economy (REP, AUTH, CASH)
└── Intelligence (interface layer)
    ├── Dashboards, proof surfaces, workflow galleries
    └── Operator tooling and public API
```

## What This Contract Prohibits

- Leading with "research infrastructure" or "governance-first" before explaining what the user actually gets.
- Describing Meridian as a research platform without first establishing Loom as a usable product.
- Hiding the install/run experience behind governance jargon.
- Removing governance/proof content — it must remain, but positioned as a trust advantage, not the entry point.
